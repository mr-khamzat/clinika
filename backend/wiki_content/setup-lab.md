# Настройка лабораторной интеграции

## Когда нужна

Если в клинике или сети есть отправка анализов в стороннюю лабораторию (Гемотест, Инвитро, КДЛ, СитиЛаб). Без интеграции врач выписывает направление на бумаге, пациент несёт его в лабораторию, результаты приходят пациенту вне платформы. С интеграцией:

- Врач создаёт заявку в кабинете — она автоматически уходит в лабораторию.
- Результат возвращается через API и попадает в медкарту пациента.
- Пациент видит результаты в своём кабинете и в чате.

## Поддерживаемые провайдеры

| Провайдер | Скорость интеграции | Формат API |
|---|---|---|
| Гемотест | REST | JSON |
| Инвитро | SOAP | XML |
| КДЛ | REST + S3 | JSON + PDF |
| СитиЛаб | REST | JSON |
| Custom | по согласованию | любой |

## Что подготовить

| Что | Где взять |
|---|---|
| Договор с лабораторией | у лаборатории |
| Контрагент-код (для биллинга) | у лаборатории |
| API ключ / SOAP credentials | у лаборатории |
| Список услуг (price-list) | у лаборатории |
| Точку доставки результатов | URL вашего webhook |

## Шаги

### 1. Подписать договор

Договор с лабораторией на отгрузку через API (B2B-канал). Цены, обычно, в 2-3 раза ниже розничных.

### 2. Получить API доступ

Лаборатория выдаёт `client_id` и `secret` после теста интеграции. Тестовая среда сначала, потом боевая.

### 3. Импорт price-list

```http
POST /admin/lab/providers/{provider}/price-list/import

{
  "format": "xlsx",
  "url": "https://...price-list.xlsx"
}
```

Или загрузка файла через UI кабинета super_admin → **Лаборатории → Импорт прайса**.

После импорта появляются услуги в `lab_services` со своими ценами для каждого тенанта.

### 4. Настройка в платформе

Кабинет super_admin → **Лаборатории → Подключить**:

```yaml
provider: gemotest
client_id: GMT_12345
api_secret: <encrypted>
base_url: https://api.gemotest.ru/v2
result_webhook_secret: <generated>
delivery_methods:
  - pdf_to_patient    # автоматически в кабинет
  - email_to_patient  # на email
  - sms_link          # SMS со ссылкой
default_clinic_id: 01HF...   # клиника-отправитель по умолчанию
```

### 5. Назначение врачам прав

Кабинет manager → **Сотрудники → Врач → Права**:

- `can_order_lab` — может выписывать направления в лабораторию.
- `can_view_lab_results` — видит результаты в карточке пациента.

### 6. Тестовая заявка

```http
POST /doctor/lab/orders/test

{
  "provider": "gemotest",
  "tests": ["CBC"]
}
```

Создаётся заявка в тестовой среде, через 2 минуты приходит mock-результат.

## API endpoints

### Создание заявки

```http
POST /doctor/lab/orders

{
  "patient_id": "01HF...",
  "provider": "gemotest",
  "tests": ["CBC", "GLU", "TSH"],
  "delivery_method": "pdf_to_patient",
  "urgent": false,
  "doctor_comment": "Контроль перед приёмом"
}
```

Response:

```json
{
  "order_id": "01HF...",
  "external_id": "GMT-2026-00123",
  "status": "sent_to_lab",
  "expected_ready_at": "2026-05-13T18:00:00Z",
  "total_amount": 1650
}
```

### Статус заявки

```http
GET /doctor/lab/orders/{id}
```

Статусы: `created → sent_to_lab → in_progress → result_ready → delivered → archived`.

### Webhook от лаборатории

Лаборатория шлёт POST в `/integrations/lab/{provider}/result-webhook`:

```json
{
  "external_id": "GMT-2026-00123",
  "status": "ready",
  "result_url": "https://gemotest.ru/r/abc",
  "result_pdf_url": "https://...result.pdf",
  "values": [
    { "code": "HGB", "value": "145", "unit": "g/L", "reference": "120-160" }
  ]
}
```

Платформа:

1. Скачивает PDF (или сохраняет URL).
2. Парсит значения и сохраняет в `lab_results`.
3. Доставляет пациенту (по выбранному `delivery_method`).
4. Уведомляет врача.

### Просмотр результата

```http
GET /doctor/lab/orders/{id}/result
GET /doctor/lab/orders/{id}/result.pdf
GET /patient/lab/orders/{id}/result.pdf
```

## Где найти в UI

Кабинет врача:

- В карточке пациента — раздел **Анализы**.
- Кнопка «Назначить анализы» — модал с поиском тестов из price-list.
- Результаты с цветовой подсветкой отклонений.

Кабинет пациента:

- **Анализы** — список заявок и результатов.
- При новом результате — push + email.

Кабинет manager:

- **Лаборатория → Заявки** — все заявки по сети.
- Финансовый отчёт по лаборатории (отдельно от приёмов).

## Биллинг лабораторных услуг

Два варианта расчёта:

1. **Клиника платит лаборатории, пациент клинике.** Клиника зарабатывает на марже. Цена пациенту = price-list × markup_pct.
2. **Пациент платит лаборатории напрямую.** Клиника получает % attribution. Используется при «нулевой марже» или агентской модели.

Выбор — в настройках провайдера: `billing_model: markup | agent`.

| Таблица | Описание |
|---|---|
| `lab_providers` | подключённые провайдеры |
| `lab_services` | каталог услуг с ценами |
| `lab_orders` | заявки |
| `lab_results` | результаты с парсированными значениями |
| `lab_invoices` | биллинг лабораторных услуг |

## Безопасность

- API ключи лаборатории хранятся зашифрованными (Fernet).
- Webhook от лаборатории проверяется по подписи или IP whitelist.
- Результаты PDF хранятся в encrypted S3-бакете.
- Доступ пациента к результату — только после OTP-подтверждения (опционально).

## FAQ

**Что если лаборатория не прислала webhook?** Каждые 30 минут платформа polls `/orders/{external_id}` у провайдера. Найдены изменения → подтягивает.

**Можно ли отменить заявку?** Только до отгрузки в лабораторию. После — невозможно, оплата сохраняется.

**Сколько хранится PDF результата?** 5 лет (требование МЗ РФ для медицинской документации).

**Что если результаты неполные?** Статус `partial`, пациент видит то, что готово, + сообщение «Часть анализов ещё в работе».
