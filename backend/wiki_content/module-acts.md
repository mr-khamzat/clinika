# Модуль «Акты и документы»

Бесплатный встроенный модуль формирования медицинских документов: акты выполненных работ, инвойсы, согласия, договоры. PDF-генерация через WeasyPrint, электронная подпись через OTP.

## Что это даёт клинике

- Документооборот между клиниками внутри сети (InterClinicInvoice + Act).
- Акты для пациента-юрлица (страховые, корпоративные клиенты).
- Электронная подпись актов без бумаги (OTP по SMS/email).
- Контроль просроченных актов: cron автоматически помечает overdue + шлёт алерт.

## Что входит технически

- **Акты** (`Act`, `InterClinicAct`): номер, дата, контрагент, позиции услуг, сумма, статус (draft / signed / paid / overdue / cancelled).
- **Связь с инвойсом** (`Invoice`, `InterClinicInvoice`): акт всегда привязан к инвойсу.
- **PDF-генерация**: WeasyPrint рендерит HTML-шаблон Jinja2 в PDF. С печатями, подписями, реквизитами.
- **OTP-подпись**: код по SMS / email подтверждает подпись акта стороной клиента. Хранится в `Act.signed_at`, `Act.signed_by_otp`.
- **Cron** (`acts_overdue_check`): раз в день помечает не подписанные / не оплаченные акты как `overdue`.
- **Audit**: каждое действие (подпись, оплата, отмена) логируется в `audit_log`.

## Как настроить

1. Заполнить реквизиты тенанта в `/admin/tenant/settings`: ИНН, КПП, ОГРН, банковские реквизиты, юр. адрес.
2. Загрузить факсимиле подписи руководителя и печать (PNG с прозрачным фоном).
3. Настроить шаблоны актов: `/admin/acts/templates` — `act_default.html.j2`, `act_inter_clinic.html.j2`.
4. SMTP или SMS-провайдер для отправки OTP (см. `setup-smtp.md` или `setup-telegram.md`).
5. Опционально — cron на overdue-check (по умолчанию запускается ежедневно в 04:00).

## Как пользоваться

### Сгенерировать акт

1. `/admin/acts/new` — выбрать инвойс (или создать новый).
2. Заполнить контрагента, услуги, сумму.
3. Кнопка `POST /acts/generate` → создаётся PDF, статус `draft`.
4. Можно скачать или отправить контрагенту.

### Подписание клиентом

1. Клиент получает email/SMS со ссылкой и OTP-кодом.
2. Открывает ссылку → видит PDF акта.
3. Вводит OTP-код → акт переходит в статус `signed`, `signed_at` фиксируется.
4. Альтернатива — кнопка «Подписать электронно» прямо в кабинете: `POST /acts/{id}/sign-electronic`.

### Оплата

1. После подписи — кнопка «Оплатить»: `POST /acts/{id}/pay` (если оплата через ЮKassa).
2. Или оплата по выставленному счёту банковским переводом.
3. По webhook от провайдера или вручную статус → `paid`.

## API endpoints

- `GET /acts` — список (фильтры: статус, период, контрагент).
- `POST /acts/generate` — создать акт по инвойсу.
- `POST /acts/{act_number}/sign` — подписать (OTP).
- `POST /acts/{act_number}/pay` — отметить оплаченным.
- `POST /acts/check-overdue` — ручной запуск проверки overdue.
- `GET /acts/{act_id}/pdf` — скачать PDF.
- `POST /acts/{act_id}/sign-electronic` — электронная подпись через кабинет.
- `GET /inter-clinic-acts/{act_id}/pdf` — PDF межклинического акта.
- `POST /inter-clinic-acts/{act_id}/sign-electronic` — подписать межклинический акт.

## Шаблоны документов

В `/opt/clinika/backend/app/templates/acts/`:
- `act_default.html.j2` — стандартный акт выполненных работ.
- `act_inter_clinic.html.j2` — межклинический акт.
- `invoice.html.j2` — счёт.
- `agreement_consent.html.j2` — согласие на обработку ПД.

Все шаблоны переопределяются на уровне тенанта (white-label).

## Известные ограничения

- ЭЦП КриптоПро / Госуслуги — не интегрировано (только OTP).
- PDF/A для архивного хранения — не реализовано.
- Нет интеграции с СБИС / Контур.Диадок (EDI-обмен). TODO.
- Шаблоны редактируются только через файлы Jinja2, нет UI-редактора.
