# Модуль «Учёт инвентаря»

**1 990 ₽/мес · 21 492 ₽/год** · ключ `inventory` · категория `operations` · подключается в `/admin → Тарифы → Подключаемые модули`.

Полный учёт расходных материалов, оборудования, остатков и движений между клиниками сети. Алерты по низким остаткам, инвентаризация по штрих-коду, импорт каталога CSV.

## Что это даёт клинике

- Перестали «заканчиваться шприцы» в неподходящий момент — алерты приходят за 5-7 дней до zero.
- Инвентаризация раз в месяц вместо «когда вспомним» — данные всегда актуальны.
- Контроль расхода: видно, какая клиника жжёт перевязочный материал быстрее остальных.
- Списание по приёмам: автоматическое «−1 шприц» при выполнении процедуры.

## Что входит технически

- **Каталог** (`InventoryItem`): артикул, наименование, единица измерения, минимальный остаток, поставщик, штрих-код.
- **Категории** (`InventoryCategory`): шприцы, перевязка, реактивы, бытовая химия, оборудование и т.п.
- **Остатки** (`InventoryStock`) — на каждую клинику отдельно. Текущий остаток + резерв.
- **Движения** (`InventoryMovement`): приход / списание / перемещение между клиниками / списание по приёму. С документом-основанием.
- **Инвентаризация** (`InventoryCount`): сверка факт vs учёт. Расхождения требуют комментария.
- **Алерты**: при опускании остатка ниже `minimum_stock` — пуш менеджеру + email.
- **Импорт каталога**: CSV с колонками `sku, name, unit, min_stock, category`.

## Как настроить

1. Активировать модуль в `/admin → Тарифы → Подключаемые модули`.
2. Создать категории в `/admin/inventory/categories` (10-15 категорий обычно достаточно).
3. Импортировать каталог: `POST /inventory/items/import-csv` (или вручную).
4. Задать `minimum_stock` для критичных позиций (расходники врача).
5. (Опционально) Назначить ответственного: роль `inventory_manager` или просто `manager` каждой клиники.

## Как пользоваться

### Приёмка товара

1. `/admin/inventory/movements/income` — создать приход.
2. Указать клинику-получатель, позиции, количество, документ-основание (накладная).
3. Остатки обновляются автоматически.

### Перемещение между клиниками

1. `POST /inventory/movements/transfer` — указать клинику-источник, получатель, позиции.
2. Двойная запись: списание с одной клиники → приход на другую.

### Списание

1. `POST /inventory/movements/outgoing` — для расхода без привязки к приёму (хозяйственные нужды).
2. `POST /inventory/movements/write-off` — для порчи / просрочки.
3. Автоматическое списание по приёму — настраивается в правилах услуг.

### Инвентаризация

1. `POST /inventory/stocks/count` — стартует сверка.
2. Сотрудник идёт по складу, считает факт по штрих-коду или вручную.
3. После завершения система выводит расхождения, требует комментарий.

## API endpoints

- `GET /inventory/items` — каталог.
- `POST /inventory/items` — создать позицию.
- `GET /inventory/items/{id}` / `PATCH` / `DELETE` — управление.
- `POST /inventory/items/import-csv` — импорт каталога.
- `GET /inventory/stocks` — текущие остатки.
- `POST /inventory/stocks/count` — инвентаризация.
- `GET /inventory/movements` — журнал движений (фильтры: клиника, тип, период).
- `POST /inventory/movements/income` — приход.
- `POST /inventory/movements/outgoing` — расход.
- `POST /inventory/movements/transfer` — перемещение.
- `POST /inventory/movements/write-off` — списание.
- `GET /inventory/alerts` — текущие алерты (низкие остатки).

## Известные ограничения

- Нет интеграции с поставщиками (типа «автозаказ»). Заказы создаются вручную.
- Нет учёта серий и сроков годности — TODO для медицинской лицензии.
- Нет себестоимости и финансового учёта — только количественный.
- Штрих-код сканируется через камеру браузера (html5-qrcode), USB-сканер не интегрирован.
