# Модуль «CMS — страницы тенанта»

Бесплатный встроенный движок страниц для каждого тенанта. Создание ссылок навигации меню и публичных страниц (О нас, Услуги, Контакты, Лицензии, Политика конфиденциальности). Управление CRUD-операциями (создание/редактирование/удаление страниц) требует активного модуля **White-Label брендинг** (`white_label`, 3 990 ₽/мес).

## Что это даёт клинике

- Свой сайт «из коробки» без отдельной разработки.
- SEO-страницы для агрегаторов и Google: услуги, врачи, контакты.
- Юридические страницы (Политика, Согласие 152-ФЗ) — генерируются из шаблонов.
- Меню навигации настраивается под бренд франшизы.

## Что входит технически

- **Страницы** (`CMSPage`): slug, title, content (Markdown + DOMPurify санитизация), мета-теги, статус (draft/published).
- **Меню** (`CMSMenuItem`): иерархическое меню публичного сайта, иконки, порядок.
- **Тема** (`CMSTheme`): цветовая палитра тенанта (oklch), логотип, фавикон.
- **CSS-токены**: `/cms/theme/css` отдаёт сгенерированный CSS с переменными бренда → подключается в публичных страницах.
- **Multi-tenancy**: каждый тенант видит и редактирует только свои страницы (resolve через slug или host).
- **Доступ**: чтение публичное (`/p/{slug}/{page_slug}`), редактирование — только при активном `white_label`.

## Как настроить

1. **Тема**: `/admin/cms/theme` — палитра (primary / secondary / accent), логотип. Применяется к публичным страницам.
2. **Меню**: `/admin/cms/menu` — добавить пункты: Услуги, Врачи, Контакты, О нас. Можно вложенные подпункты.
3. **Страницы** (требуется `white_label`):
   - `/admin/cms/pages` — список.
   - Создать → задать slug (`about`, `contacts`, `privacy`), title, Markdown-контент.
   - Опубликовать (`is_published = true`).
4. Публичная ссылка — `https://клиниксеть.рф/p/{tenant_slug}/{page_slug}`.

## Как пользоваться

### Создание страницы

1. `/admin/cms/pages/new` — slug, title.
2. Markdown-редактор — поддержка GFM (таблицы, чекбоксы, fenced code).
3. Превью → опубликовать.

### Редактирование меню

1. `/admin/cms/menu` — drag-and-drop иерархия.
2. Каждый пункт: заголовок, ссылка (внутренняя на страницу или внешняя), иконка, видимость.

### Применение темы

1. `/admin/cms/theme` — палитра oklch.
2. Сразу видно превью.
3. После сохранения — `/cms/theme/css` отдаёт новые CSS-переменные. SSR/SPA подключают.

## API endpoints

- `GET /cms/theme` — тема тенанта (resolve по slug или host).
- `GET /cms/theme/css` — CSS-переменные.
- `GET /cms/menu` — пункты меню (публично).
- `GET /cms/pages` — список страниц.
- `GET /cms/pages/{slug}` — конкретная страница.
- `POST /cms/pages` — создать (требует `require_module("white_label")`).
- `PUT /cms/pages/{slug}` — обновить (требует `white_label`).
- `DELETE /cms/pages/{slug}` — удалить (требует `white_label`).

## Известные ограничения

- Markdown санитизируется DOMPurify — теги `<script>`, `<iframe>`, inline event handlers вырезаются.
- Нет визуального редактора (типа TinyMCE) — только Markdown с превью.
- Загрузка изображений в страницы — через uploads tenant'а, нет встроенного медиа-менеджера.
- SEO мета-теги (og:image, og:description) — текстовые поля в `CMSPage.meta_json`.
- Нет версионирования страниц (TODO).

## SEO

Каждая страница автоматически имеет:
- `<title>` из `CMSPage.title`.
- `<meta name="description">` из `CMSPage.meta_description`.
- `<link rel="canonical">` на полный URL.
- `og:title`, `og:description`, `og:image` (если задано в meta_json).
- Sitemap.xml — генерируется автоматически из опубликованных страниц.
- robots.txt — управляется тенантом через CMS-настройки.

## Best practices

1. Slug на латинице (`about`, `contacts`), без транслита.
2. Title до 60 символов (для SERP).
3. Description 150-160 символов.
4. Markdown — заголовки иерархично (`##` → `###`).
5. Изображения с alt-текстом (для SEO + a11y).
6. Внутренние ссылки между страницами CMS (через `[Текст](page-slug)`).
