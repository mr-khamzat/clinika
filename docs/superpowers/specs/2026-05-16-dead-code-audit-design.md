# Dead-code audit Клиники — Design

**Дата:** 2026-05-16
**Автор:** brainstorming-сессия с пользователем
**Цель:** За один прогон выявить мёртвый/неиспользуемый код в проекте Клиники
(~210 000 строк, 377 Python + 328 JS/JSX файлов) и прислать сводный отчёт в
Telegram. **Ничего не удаляем** — только отчёт.

---

## 1. Контекст

Проект `/opt/clinika/` на сервере 212.57.118.126 (Ubuntu 24.04, Docker
Compose). Содержит:

- `backend/` — FastAPI приложение, 377 `.py` файлов, ~88 700 строк
- `frontend/` — React+Vite, 328 `.jsx/.js` файлов, ~120 600 строк
- Существующих тестов: 13 файлов

Существует исторический долг — несколько слоёв реализации, дублирующие
endpoint'ы, лежащие в репо «на всякий случай» компоненты (`*_old.jsx`,
`*_v1`, закомментированные блоки). Каталог никогда не подвергался
системному dead-code аудиту.

## 2. Цели и не-цели

**Цели:**
- Получить ранжированный по риску список кандидатов на удаление
- Сводка по TG, полный markdown на сервере
- Сделать процесс воспроизводимым (скрипт можно перезапустить через месяц)

**Не-цели (out-of-scope этой задачи):**
- ❌ Удалять код
- ❌ Покрывать тестами
- ❌ Оптимизировать производительность
- ❌ Чистить alembic-миграции
- ❌ Реализовывать авто-фикс / IDE-интеграцию

## 3. Что считаем dead-кодом

### Backend (Python)

| Категория | Сигнал |
|-----------|--------|
| Endpoint без потребителя | URL endpoint'а не встречается в `api.<method>('…')` фронта |
| Orphan router | Файл `app/routers/*.py` не подключён в `app/main.py` через `include_router` |
| Orphan service | Файл `app/services/*.py` без импортов из других файлов backend'а |
| Unused function | Функция верхнего уровня без вызовов (через `vulture`) |
| Старые миграции | (отдельная задача, в этом аудите не покрываем) |

### Frontend (JS/JSX)

| Категория | Сигнал |
|-----------|--------|
| Orphan component | `.jsx` файл не упомянут ни в одном `import` и нет в `App.jsx` Routes / `lazy()` |
| Unused util | `.js` в `lib/`, `utils/`, `helpers/` без импортов |
| Закомментированный код | Блоки `// …` или `/* … */` длиной > 5 строк подряд |
| Артефакты разработки | `console.log`, `debugger`, `TODO:` без тикета |

### Общее

| Категория | Сигнал |
|-----------|--------|
| Backup-файлы | Маркеры в имени: `_old`, `_backup`, `.bak`, `_v1`, `_copy` |

## 4. Архитектура решения

**Артефакт:** Python-скрипт `/opt/clinika/tools/audit/dead_code_audit.py`

Скрипт состоит из трёх независимых слоёв:

### L1 — Тулинги (грубый список)
- `vulture backend/app/` (Python dead-code)
- `knip` в `frontend/` (или fallback `ts-prune --error 0`) — если установлен
- Результаты обоих сохраняются в `raw/` рядом с отчётом

### L2 — Cross-stack анализ (точный список)
- Парсер backend: regex по всем `@router.<method>("…")` собирает `(file, url_pattern)`
- Парсер frontend: regex по всем `api\.(get|post|put|delete|patch)\(['"](.+?)['"]` собирает `(file, url)`
- Сопоставление: для каждого backend-URL ищем фронт-вызов с тем же путём (учёт path-параметров через regex)
- Для frontend компонентов: парсим `import … from '…'` и `lazy(() => import('…'))` по всему фронту; компоненты без входящих ссылок и без записи в App.jsx Routes → orphan

### L3 — Классификация риска
Каждому кандидату присваивается тег:

- 🟢 **safe** — нет НИ ОДНОГО упоминания (ни в коде, ни в комментариях)
- 🟡 **likely** — упоминается только в комментариях/документации
- 🔴 **review** — есть совпадение по подстроке (например, URL шаблон), но нет явного вызова

## 6. Запуск и доставка

Однократный запуск из SSH:

```
cd /opt/clinika
python3 tools/audit/dead_code_audit.py
```

Скрипт:
1. Читает `TG_BOT_TOKEN` из `/opt/meshcentral-bot/.env`
2. Запускает L1, L2, L3
3. Пишет `tools/audit/report-2026-05-16.md` + сырые выводы тулов в `tools/audit/raw/`
4. Отправляет TG-сообщение через `sendMessage` на `chat_id=293633093`
5. Если основное сообщение > 4 KB — режется на блоки или отправляется как document (`sendDocument`)

## 7. Тестирование

Скрипт single-shot, не нужны юнит-тесты сложной библиотеки. Минимальная
проверка:

- Dry-run флаг `--no-telegram` (только пишет отчёт, не шлёт)
- Smoke-тест: после первого прогона — глазами проверить, что в категориях
  🟢/🟡/🔴 разумные кандидаты (нет очевидно живых файлов в 🟢)

## 8. Риски и митигация

| Риск | Митигация |
|------|-----------|
| Динамические импорты в backend (`importlib`) → ложные 🟢 | Добавить в L3 шаг: grep по имени файла без расширения по всему репо |
| Frontend компоненты, используемые через `React.lazy(import('…'))` | Парсер L2 учитывает паттерн lazy() явно |
| Endpoint'ы, дёргаемые из внешних систем (МИС webhook, бот) | В L3 теге `review` отдельно отметить endpoint'ы без явного фронт-вызова — пользователь решает |
| `knip`/`ts-prune` не установлены | Скрипт делает fallback: если тула нет → пропускает L1 для фронта, делает только L2 |
