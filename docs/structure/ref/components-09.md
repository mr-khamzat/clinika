# components [09] — Системные карточки, телемед-комната и wellness-партнёры

Группа из 5 презентационных React-компонентов фронтенда (`frontend/src/components/`), относящихся к трём разным доменам, но объединённых тем, что все они — **«листовые» UI-компоненты**: их монтируют секции более высокого уровня (`*Section.jsx`), а сами они в роутинге не участвуют. Стилизация выполнена в едином ключе проекта — inline-стили + Tailwind-классы + Material Symbols (`material-symbols-outlined`), без CSS-модулей. Бизнес-логику с сетью несут только два из пяти (`DisasterModeToggle`, `TelemedRoomModal`) — они напрямую дёргают единый axios-инстанс `../../api`; остальные три (`HealthCard`, `CategoryTabs`, `PartnerCard`) — чистые «глупые» компоненты, получающие всё через props и поднимающие события наверх через колбэки.

Домены группы:
- **system/** — административная панель состояния системы (Глава 10): аварийный режим и KPI-карточки здоровья.
- **telemed/** — видео-комната телемедицины (WebRTC + WebSocket) со стороны сотрудника клиники.
- **wellness/** — каталог партнёров оздоровления (Глава 10): табы категорий и карточка партнёра.

## `frontend/src/components/system/DisasterModeToggle.jsx`

- **Назначение:** Hero-карточка статуса + два подтверждающих модала для глобального аварийного режима (disaster-mode). При включении вся не-критичная запись в системе блокируется (только чтение + emergency endpoints) — применяется при потере backup-ов, миграциях БД, инцидентах безопасности.
- **Ключевые элементы:**
  - `default export DisasterModeToggle({ state, onChanged })` — главный компонент.
  - Внутренняя `fmtDate(iso)` — локализованное `ru-RU` форматирование даты включения.
  - Внутренние async-хендлеры `enable()` / `disable()`; локальный стейт `openEnable`, `openDisable`, `reason`, `busy`.
  - `enabled = !!state?.enabled` — вычисляемый флаг, управляющий зелёным/красным градиентом hero-карты.
- **Эндпоинты:** компонент сам делает POST-запросы (это не роутер, но вызовы к API важны для понимания):

  | Метод | Путь | Доступ/роль | Принимает | Возвращает | Назначение |
  |-------|------|-------------|-----------|------------|------------|
  | POST | `/admin/system/enable-disaster-mode` | admin (вызывается из админ-секции) | `{ reason }` (≥10 символов) | — | Активировать аварийный режим |
  | POST | `/admin/system/disable-disaster-mode` | admin | — | — | Вернуть систему в штатный режим |
- **Зависимости:** `../../api` (axios-инстанс), из `../../design` — `useToast`, `Modal`, `Button`. Состояние (`state`) и колбэк `onChanged` приходят от родителя (`AdminSystemStatusSection`).
- **Где менять для типовых задач:**
  - Изменить путь/тело API аварийного режима — строки 47 (enable) и 62 (disable).
  - Поменять минимальную длину причины (сейчас `< 10`) — строка 41.
  - Текст предупреждения в модале включения — блок строк 178–182.
  - Визуал hero (градиенты, иконки `crisis_alert`/`verified`) — строки 79–104.
- **Подводные камни:**
  - Валидация причины только клиентская (`reason.trim().length < 10`) — backend должен валидировать повторно.
  - Чистый презентационный/контейнерный компонент без tenant_id-логики; disaster-mode глобален (на уровне сети), не привязан к клинике.
  - При ошибке показывается `e?.response?.data?.detail` — рассчитывает на стандартный формат ошибки FastAPI.
- **Строк:** 235

## `frontend/src/components/system/HealthCard.jsx`

- **Назначение:** Универсальная KPI-карточка для секции `AdminSystemStatusSection` — отображает одну метрику здоровья (latency, диск, статус сервиса и т.п.) с цветовой индикацией и опциональным прогресс-баром.
- **Ключевые элементы:**
  - `default export HealthCard({ icon, title, value, unit, tone, hint, usagePct, okStatus })`.
  - Константа `PALETTE` — 4 темы (`ok`/`warn`/`bad`/`neutral`) с цветами рамки, фона и акцента.
  - `useMemo`-хук `autoTone` — автоматически выбирает тему: из `usagePct` (≥90 → bad, ≥75 → warn, иначе ok) либо из булева `okStatus`, иначе берёт переданный `tone`.
- **Эндпоинты:** нет (чистый презентационный компонент, сеть не трогает).
- **Зависимости:** только `useMemo` из `react`. Никаких внутренних модулей проекта — полностью изолирован, переиспользуем где угодно. Цвета захардкожены в `PALETTE`, фон/текст карточки берут CSS-переменные (`--surface`, `--border`, `--fg*`) с фолбэками.
- **Где менять для типовых задач:**
  - Поменять пороги цветовой индикации usage — строки 39–42 (`>= 90` / `>= 75`).
  - Добавить новую цветовую тему — расширить `PALETTE` (строки 26–31) и передавать её в `tone`.
  - Изменить вид прогресс-бара — блок строк 102–119.
  - Иконка ✓/✗ при `okStatus` — строки 77–82.
- **Подводные камни:**
  - `value ?? '—'` — `0` отобразится как `0` (не как «—»), а `null/undefined` — как «—». Если нужно скрывать нули, логику менять здесь (строка 91).
  - Цвета палитры захардкожены и НЕ темизируются через CSS-переменные — при тёмной теме индикаторы останутся светлыми.
- **Строк:** 123

## `frontend/src/components/telemed/TelemedRoomModal.jsx`

- **Назначение:** Полноэкранная модалка видео-консультации со стороны сотрудника клиники (врач/регистратор/менеджер). Содержит весь WebRTC-клиент: захват камеры/микрофона, обмен SDP/ICE через WebSocket-сигналинг, демонстрацию экрана, чат с файлами и выписку электронного рецепта. Самый сложный и «толстый» компонент группы.
- **Ключевые элементы:**
  - `default export TelemedRoomModal({ sessionId, onClose })`.
  - Вспомогательный `CtrlBtn({ icon, active, onClick, danger, title })` — круглая кнопка медиа-контролов (внизу файла).
  - Константа `DEFAULT_RTC_CONFIG` — STUN-серверы Google + bundle/rtcpMux политики (фолбэк, если backend не вернул свой ICE-config).
  - Обилие `useRef`: `wsRef`, `pcRef` (RTCPeerConnection), `localStreamRef`, `screenStreamRef`, `localVideoRef`, `remoteVideoRef`, `pendingIceRef` (буфер ICE до установки remote-description), `startedAtRef`, `cleanupRef`.
  - Главный init-`useEffect` (строки 68–192): ICE-config → getUserMedia → RTCPeerConnection → WebSocket-сигналинг → загрузка истории чата.
  - Хендлеры: `sendWs`, `toggleMic`, `toggleCam`, `toggleScreenShare`/`stopScreenShare`, `sendChatText`, `sendChatFile`, `submitRx`, `handleEnd`, `cleanup`, `fmtDur`.
  - Конечный автомат `connState`: `connecting → waiting → connected → ended`.
- **Эндпоинты:** компонент сам обращается к API и WS (важная карта сети телемед-сессии):

  | Метод | Путь | Доступ/роль | Принимает | Возвращает | Назначение |
  |-------|------|-------------|-----------|------------|------------|
  | GET | `/telemed/sessions/{id}/ice-config` | сотрудник клиники (Bearer) | — | `{ iceServers }` (TURN/STUN) | Получить ICE-конфиг для WebRTC |
  | WS | `/telemed/ws/doctor/{session_id}?token=…` | сотрудник | сигналинг: offer/answer/ice_candidate/chat | те же типы сообщений | Сигналинг WebRTC + чат |
  | POST | `/telemed/sessions/{id}/start` | сотрудник | — | — | Зафиксировать старт приёма (при connected) |
  | GET | `/telemed/sessions/{id}/messages` | сотрудник | — | `[message]` | Загрузить историю чата |
  | POST | `/telemed/sessions/{id}/messages` | сотрудник | multipart `text` и/или `file` | `message` | Отправить текст/файл в чат |
  | POST | `/telemed/sessions/{id}/prescription` | сотрудник | `{ content }` (Markdown) | — | Сохранить электронный рецепт |
  | POST | `/telemed/sessions/{id}/end` | сотрудник | — | — | Завершить сессию |
- **Зависимости:** `../../api` (axios), `../../config` → `API_BASE` (для построения WS-URL заменой `http`→`ws`), `../../store/auth` → `useAuthStore` (берёт `token` для авторизации WS через query-параметр), из `../../design` — `Button`, `Modal` (модал рецепта). Вызывается из `WeekScheduleSection` (через ApptModal) и `TelemedicineSection`.
- **Где менять для типовых задач:**
  - Добавить TURN-сервер по умолчанию — `DEFAULT_RTC_CONFIG` (строки 29–36).
  - Изменить разрешение/параметры захвата камеры — `getUserMedia` (строки 83–86).
  - Добавить новый тип WS-сообщения — `switch (msg.type)` в `ws.onmessage` (строки 135–167).
  - Логика демонстрации экрана (`replaceTrack`) — `toggleScreenShare`/`stopScreenShare` (строки 232–263).
  - Формат/поля рецепта — `submitRx` (строки 304–320) и модал (строки 549–582).
  - Очистка ресурсов при закрытии — `cleanup()` (строки 329–348); важно при добавлении новых стримов/коннектов.
- **Подводные камни:**
  - **Жёсткая очистка обязательна:** `cleanup()` останавливает все треки и закрывает PC/WS; флаг `cleanupRef` гасит ложный `connState='ended'` при намеренном закрытии WS (строки 170–172). Любой новый ресурс надо добавлять в `cleanup`, иначе утечёт камера/микрофон.
  - **ICE-буфер:** кандидаты, пришедшие до `setRemoteDescription`, складываются в `pendingIceRef` и применяются после обработки offer (строки 140–143, 151–156) — типовая WebRTC-ловушка, не ломать порядок.
  - **Токен в URL WS:** `token` передаётся query-параметром (строка 128) — попадает в логи прокси; это особенность текущей реализации сигналинга.
  - Определение «своего» сообщения чата `mine` опирается сразу на несколько полей (`sender_role`/`from_role` ∈ doctor/staff, строка 456) — бэкенд возвращает неунифицированную схему, при изменении формата сверять здесь.
  - `eslint-disable react-hooks/exhaustive-deps` на init-эффекте (строка 191) — эффект завязан только на `sessionId`; не добавлять зависимостей бездумно (пересоздаст всю комнату).
  - `z-[10000]` (строка 359) — модалка рисуется поверх всего; конфликтует с другими оверлеями при высоком z-index.
- **Строк:** 603

## `frontend/src/components/wellness/CategoryTabs.jsx`

- **Назначение:** Горизонтальные скроллящиеся табы-«пилюли» для фильтрации по категориям wellness-партнёров. Общий компонент для `PatientWellnessSection` и `AdminWellnessSection`.
- **Ключевые элементы:**
  - **Именованный экспорт `WELLNESS_CATEGORIES`** — массив-источник истины категорий: `all`, `fitness`, `spa`, `nutrition`, `psychology`, `yoga`, `other` (id + label + Material-иконка). Это канонический список категорий wellness во фронте.
  - `default export CategoryTabs({ value = 'all', onChange, counts = {} })` — рендерит пилюли, активная подсвечивается градиентом, опционально показывает бейдж-счётчик `counts[id]`.
- **Эндпоинты:** нет (чистый презентационный компонент).
- **Зависимости:** нет внешних импортов вообще — полностью автономен. Однако `WELLNESS_CATEGORIES` импортируется другими wellness-секциями как справочник, поэтому правки массива влияют на весь домен.
- **Где менять для типовых задач:**
  - Добавить/переименовать категорию — массив `WELLNESS_CATEGORIES` (строки 14–22). **Важно:** id-шники должны совпадать с категориями на backend и с ключами в `PartnerCard` (`CATEGORY_THEME`).
  - Изменить активный градиент/вид пилюли — строки 41–47.
  - Логика бейджа-счётчика (показ только при `> 0`) — строки 56–69.
- **Подводные камни:**
  - **Дублирование справочника категорий:** список id здесь должен быть синхронен с `CATEGORY_THEME` в `PartnerCard.jsx` (строки 19–26). Это два независимых источника — при добавлении категории правьте оба файла, иначе у новой категории не будет темы/иконки в карточке.
  - `all` присутствует в табах, но в `CATEGORY_THEME` карточки его нет (логично — это псевдо-категория «Все»).
- **Строк:** 76

## `frontend/src/components/wellness/PartnerCard.jsx`

- **Назначение:** Премиум-карточка одного wellness-партнёра в сетке `PatientWellnessSection`: пастельный градиент-хедер с лого/иконкой, бейдж категории, плашка скидки, кнопка «Подробнее». Поддерживает заблокированное состояние (`locked`) — когда у пациента нет нужной подписки.
- **Ключевые элементы:**
  - `default export PartnerCard({ partner, locked = false, onOpen })`.
  - **Именованный экспорт `categoryLabel(cat)`** — возвращает русскую метку категории (используется секциями для подписей).
  - Константа `CATEGORY_THEME` — пастельные градиенты + иконка + label по категории (`fitness`/`spa`/`nutrition`/`psychology`/`yoga`/`other`).
  - Внутренние `themeFor(cat)` (с фолбэком на `other`) и `planLabel(key)` (карта ключей тарифов → человекочитаемые названия: `health_plus`/`health`/`premium`/`pro`).
- **Эндпоинты:** сам не вызывает; клик «Подробнее» делегируется родителю через `onOpen(partner)` (по комментарию — родитель делает `POST /click` и открывает `partner.link_url`).
- **Зависимости:** нет внешних импортов. Данные `partner` приходят сверху; `onOpen` — колбэк родителя (`PatientWellnessSection`).
- **Где менять для типовых задач:**
  - Добавить тему новой категории — `CATEGORY_THEME` (строки 19–26). **Синхронизировать с `WELLNESS_CATEGORIES` в CategoryTabs.jsx.**
  - Добавить/переименовать тариф подписки — карта `planLabel` (строки 165–173).
  - Изменить текст заблокированной кнопки — строка 158 (`Доступно с ${planLabel(...)}`).
  - Вёрстка скидки/лого — блоки строк 50–106 (header) и 125–140 (скидка).
- **Подводные камни:**
  - **Дубль справочника категорий** (см. `CategoryTabs`): `CATEGORY_THEME` и `WELLNESS_CATEGORIES` ведутся раздельно — рассинхрон ломает отображение темы.
  - Логика блокировки чисто визуальная: `locked` лишь дизейблит кнопку и показывает замок (строки 92–105, 143–159). Реальный доступ к промокоду/ссылке обязан проверять backend — клиент доверять нельзя.
  - `onError` на `<img>` (строка 66) скрывает битое лого, но НЕ показывает иконку-фолбэк (она рендерится только при отсутствии `logo_url`) — при битой ссылке хедер останется пустым.
- **Строк:** 174

### Сводка по связям группы
- **Сетевые компоненты:** `DisasterModeToggle` (2 admin-POST) и `TelemedRoomModal` (7 telemed-эндпоинтов + WS) — единственные, кто ходит в API; оба через `../../api`.
- **Чистые презентационные:** `HealthCard`, `CategoryTabs`, `PartnerCard` — без сети, всё через props/колбэки.
- **Главный риск группы:** дублирование справочника категорий wellness между `CategoryTabs.WELLNESS_CATEGORIES` и `PartnerCard.CATEGORY_THEME` — правится в двух местах.
- **Общие зависимости:** дизайн-система `../../design` (`Modal`/`Button`/`useToast`), axios `../../api`, `useAuthStore`, `API_BASE` из config.
