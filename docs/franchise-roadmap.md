# Franchise Roadmap — кабинет franchise_owner

Список будущих фич для кабинета владельца франшизы. Под каждый пункт — краткое описание и техническое замечание (источник данных, эндпоинт, модель).

## 1. Консолидированный P&L по сети

Сводный отчёт по всей франшизе: выручка -> себестоимость (зарплата врачей, расходники, аренда) -> валовая маржа -> налоги (УСН/НДС) -> чистый доход. Группировка: клиника, период (месяц/квартал/год), направление (стоматология/терапия/...).

**Тех. замечание:** агрегатор по тенантам из `payments` (выручка cash+card+online), `salary_calculations` (ЗП врачей), `expenses` (категории `rent`, `supplies`, `taxes`), `inventory_consumption` (расходники). Новый эндпоинт `/franchise-owner/finance/pnl?period=YYYY-MM&group_by=clinic|direction`. Кешировать в Redis на 1 час — пересчёт тяжёлый.

## 2. Сравнение KPI клиник (таблица-рейтинг)

Таблица: строки = клиники, колонки = ключевые метрики (выручка/врача, средний чек, conversion заявок, retention 30/90/180 дн, NPS, no-show %). Сортировка по любой колонке, цветовые индикаторы (топ-3 / нижние-3).

**Тех. замечание:** данные из `appointments` (записи, no-show), `payments` (выручка), `nps_surveys` (опросы), `referrals` (лиды/конверсия). Эндпоинт `/franchise-owner/analytics/clinic-ranking?period=last_30d`. Retention считать по таблице `patient_visits` (повторные визиты в окнах). NPS — отдельная фоновая задача собирает из СМС/email-опросов.

## 3. Royalty / паушалка калькулятор

Калькулятор расчёта контракта с новой клиникой-партнёром: пользователь выбирает модель (% с выручки / фикс/мес / гибрид / per_referral), вводит прогноз выручки, получает P&L франшизы по этой клинике на горизонте 1/3/5 лет. Конструктор шаблонов контрактов с PDF-выгрузкой.

**Тех. замечание:** чистый фронт-калькулятор + сохранение пресетов в `franchise_royalty_templates` (новая таблица: name, model_type, params_json, owner_id). PDF — серверная генерация через WeasyPrint, шаблон `templates/contracts/royalty_v1.html`. Эндпоинт `POST /franchise-owner/royalty/templates` + `GET /franchise-owner/royalty/templates/{id}/pdf`.

## 4. Перелив пациентов между клиниками (матрица рефералов)

Матрица: строки = клиника-источник, колонки = клиника-приёмник, в ячейке = количество переведённых пациентов + выручка с них. Помогает видеть, какие клиники реально работают как сеть, а какие изолированы.

**Тех. замечание:** источник — таблица `inter_clinic_referrals` (уже есть). Эндпоинт `/franchise-owner/analytics/referral-matrix?period=...` — `GROUP BY (from_clinic_id, to_clinic_id)`. На UI — heatmap (Tailwind grid + интенсивность фона по объёму). Drill-down: клик на ячейку — список пациентов.

## 5. Остатки модулей (gap-анализ)

Отчёт «какие клиники не подключили платный модуль X»: для каждого модуля каталога — список тенантов сети, у которых `is_active=false`, с потенциальной выручкой франшизы (если бы подключили по средней цене). Конверсионная воронка для апсейла.

**Тех. замечание:** данные уже в `franchise_module_grants` (используется в `/franchise-owner/modules/grants`). Новый эндпоинт `/franchise-owner/modules/gaps`: возвращает `[{module_key, missing_tenants: [...], avg_price_internal, potential_mrr}]`. На UI — карточки модулей с кнопкой «Отправить предложение всем» (создаёт задачу для менеджеров франшизы).
