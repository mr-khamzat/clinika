# Чат · Drag&drop файлов и цитирование

Две UX-улучшения чата клиники: загрузка вложений перетаскиванием и ответ с цитированием конкретного сообщения.

## Зачем это нужно

- Регистратор перетаскивает скан паспорта с рабочего стола в окно чата — без кнопок «выбрать файл».
- В тредах с историей в 30+ сообщений сложно понять, на какое именно отвечает регистратор. Quoted reply решает это — пациент видит «👆 ваше сообщение от 12:30: …», а ниже ответ.

## Drag & drop

### Поток

```
1. Пользователь тащит файл из системы → DragEnter на области чата
2. Появляется overlay «Отпустите, чтобы прикрепить»
3. Drop → handleDrop(e):
   - e.preventDefault()
   - files = e.dataTransfer.files
   - валидация (см. ниже)
   - upload через POST /api/chat/threads/{id}/attachments (FormData)
4. После 200 → сообщение со ссылкой на файл публикуется в треде
```

### Валидация

| Параметр | Лимит |
|----------|-------|
| Размер | 50 МБ на файл |
| Типы | image/*, application/pdf, application/msword, .docx, .xlsx, .zip |
| Количество за раз | до 10 файлов |
| Имя | санитизация — убираются `..`, `/`, `\` |

При нарушении — toast с описанием проблемы, файл не отправляется.

### Превью

Изображения (image/jpeg, image/png, image/webp) рендерятся inline в сообщении (max-width 400px). Остальные — как карточка «📎 имя.расширение · 2,3 МБ».

### Реализация (упрощённо)

```jsx
function ChatWindow() {
  const [dragging, setDragging] = useState(false);

  return (
    <div
      onDragEnter={() => setDragging(true)}
      onDragLeave={e => { if (e.target === e.currentTarget) setDragging(false); }}
      onDragOver={e => e.preventDefault()}
      onDrop={e => {
        e.preventDefault();
        setDragging(false);
        handleFiles(Array.from(e.dataTransfer.files));
      }}
    >
      {dragging && <div className="overlay">Отпустите файл сюда</div>}
      {/* ... */}
    </div>
  );
}
```

## Quoted reply (цитирование)

### Зачем

Когда пациент написал 5 вопросов подряд, регистратору нужно отвечать по очереди — с привязкой к конкретному вопросу.

### Поток

1. Hover на сообщении → появляется иконка «↩️».
2. Клик → над полем ввода открывается «Ответ на: <первые 80 символов>».
3. При отправке POST содержит `reply_to_id`.
4. У получателя сообщение рендерится с серой полоской слева, цитатой сверху, текстом ответа снизу.

### Структура сообщения в API

```json
{
  "id": "msg_456",
  "thread_id": "th_12",
  "body": "Да, мы записываем на 14:30.",
  "reply_to_id": "msg_123",
  "reply_to": {
    "id": "msg_123",
    "body": "А есть свободное в среду до обеда?",
    "author_name": "Иванов И.",
    "created_at": "2026-05-17T11:30:00Z"
  }
}
```

`reply_to` приходит с сервера join'ом — фронт не делает дополнительный запрос.

### UI

```
┌──────────────────────────────────────┐
│ ▎ Иванов И. · 12:30                  │
│ ▎ А есть свободное в среду до обеда? │
│                                      │
│ Да, мы записываем на 14:30.          │
└──────────────────────────────────────┘
```

Клик по цитате — плавный scroll к оригиналу + кратковременная подсветка.

### Удаление

Если оригинал удалён, цитата всё равно остаётся, но с пометкой «(сообщение удалено)».

## API

- `POST /api/chat/threads/{id}/messages { body, reply_to_id? }`
- `POST /api/chat/threads/{id}/attachments` (multipart/form-data)

## FAQ

**Можно ли цитировать своё сообщение?** Да, любое в этом треде.

**Что с drag&drop на мобильном?** Нативный drag отсутствует, есть стандартная кнопка «📎» рядом с textarea.

**Где хранятся файлы?** В S3-совместимом хранилище (MinIO) с подписанными URL на 24 часа.
