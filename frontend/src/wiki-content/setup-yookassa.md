# Настройка ЮKassa для онлайн-оплат

## Когда нужна

ЮKassa — основной платёжный провайдер платформы для онлайн-оплат пациентами. Без неё работают только cash-режимы (manager пробивает чек, выдаёт пациенту бумажный документ). С ЮKassa пациент может оплатить:

- Подписку «Здоровье+» в один клик из кабинета
- Приём заранее (предоплата)
- Услуги доп-программы лояльности

## Что подготовить

| Что | Где взять |
|---|---|
| shopId | Личный кабинет ЮKassa → Настройки магазина |
| Секретный ключ | Личный кабинет → Интеграция → API ключи |
| Webhook URL | Платформа: `https://<tenant>.клиниксеть.рф/webhooks/yookassa` |
| Webhook секрет | Сгенерировать в платформе при настройке |

Документы по 54-ФЗ:

- ИП с УСН (или ООО)
- Расчётный счёт
- Договор с оператором ОФД (Платформа ОФД, ATOL, Контур.ОФД и т.д.)

## Шаги

### 1. Регистрация в ЮKassa

1. Зайдите на yookassa.ru, заполните анкету ИП/ООО.
2. Загрузите документы. Модерация 1-3 рабочих дня.
3. После одобрения получаете `shopId` и `secret_key`.

### 2. Настройка в платформе

Кабинет manager → **Интеграции → Эквайринг**:

1. Выберите провайдер «ЮKassa».
2. Введите `shopId` и `secret_key`.
3. Скопируйте Webhook URL и Webhook секрет.
4. Нажмите «Проверить подключение» — платформа создаст тестовый платёж 1 ₽ и сразу отменит.

### 3. Webhook на стороне ЮKassa

В кабинете ЮKassa → **Интеграции → HTTP-уведомления**:

1. Добавьте URL (скопированный из платформы).
2. Подписка на события: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
3. Сохраните.

### 4. Тестовый платёж

1. Откройте кабинет пациента (тестовый аккаунт).
2. Здоровье+ → Активировать.
3. Появится виджет ЮKassa. Используйте тестовую карту `4111 1111 1111 1111`, CVC любой, дата 12/30.
4. После оплаты — статус подписки `active` в течение 5 секунд (через webhook).

### 5. Прод-режим

1. В кабинете ЮKassa переключите магазин из «Тест» в «Прод».
2. В платформе — сохранятся те же ключи, но платежи теперь реальные.
3. Сделайте проверочный платёж на 10 ₽, потом возврат.

## Поля настройки

```json
{
  "provider": "yookassa",
  "shop_id": "123456",
  "secret_key": "live_abc...",
  "webhook_secret": "platform_generated",
  "currency": "RUB",
  "vat_code": 6,
  "default_payment_method": "bank_card",
  "available_methods": ["bank_card", "sbp", "yoo_money"]
}
```

`vat_code` для 54-ФЗ:

- 1 — НДС 20%
- 2 — НДС 10%
- 6 — НДС 0% (медуслуги по ОКВЭД 86.21-86.23 — освобождение от НДС)

## Webhook payload (от ЮKassa)

Тип `payment.succeeded`:

```json
{
  "type": "notification",
  "event": "payment.succeeded",
  "object": {
    "id": "...",
    "status": "succeeded",
    "amount": { "value": "990.00", "currency": "RUB" },
    "metadata": {
      "subscription_id": "01HF..."
    }
  }
}
```

Платформа сверяет HMAC-подпись с `webhook_secret`, находит подписку по `metadata.subscription_id` и активирует её.

## Связь с ОФД

После успешного платежа платформа:

1. Создаёт запись в `fiscal_receipts`.
2. Отправляет данные в подключенный ОФД (см. [настройку ОФД](/wiki/setup-ofd)).
3. ОФД возвращает фискальный признак.
4. Чек уходит пациенту по email/SMS.

## Возвраты

```http
POST /billing/refunds

{
  "payment_id": "...",
  "amount": 990.00,
  "reason": "Отмена подписки в течение 14 дней"
}
```

Платформа вызывает `POST /v3/refunds` у ЮKassa, ждёт webhook `refund.succeeded` и корректирует ledger.

## Что делать при отказе ЮKassa

- Disaster mode включается автоматически.
- В UI пациента вместо виджета — сообщение «Онлайн-оплата временно недоступна, оплатите в клинике».
- Manager использует cash activation.

## Лимиты ЮKassa

| Параметр | Значение |
|---|---|
| Мин платёж | 1 ₽ |
| Макс платёж | 600 000 ₽ |
| Комиссия (карта) | 2.8% |
| Комиссия (СБП) | 0.7% |

Точные комиссии — по договору с ЮKassa.

## FAQ

**Почему не появляется виджет?** Проверьте, что модуль `billing_online` подключён у тенанта и `shop_id`/`secret_key` валидны.

**Webhook не приходит.** Проверьте, что URL доступен из интернета (без VPN) и https корректен. ЮKassa блокирует non-https.

**Можно ли подключить два магазина для разных клиник?** Да, ЮKassa создаёт отдельный `shop_id` для каждой клиники в рамках одного юр-лица.

**Тест-режим — это бесплатно?** Да, тестовые платежи не идут к клиенту.

## Production readiness checklist

Перед переводом ЮKassa в боевой режим:

- [ ] **ИП или ООО зарегистрировано** — без юр-лица ЮKassa договор не подпишет.
- [ ] **Расчётный счёт открыт** в банке, реквизиты переданы в ЮKassa.
- [ ] Магазин подтверждён в кабинете ЮKassa, документы (договор, паспорт, ОГРН/ОГРНИП) загружены.
- [ ] **Test-режим**: проведён тестовый платёж 1 ₽ → webhook `payment.succeeded` доходит до backend → BillingLedger обновляется.
- [ ] **Webhook URL** настроен на `https://<tenant_domain>/billing/yookassa/webhook` и доступен из интернета (без VPN, валидный HTTPS).
- [ ] `shop_id` и `secret_key` сохранены в БД в зашифрованном виде (Fernet).
- [ ] **Возвраты протестированы**: `POST /billing/refunds` → webhook `refund.succeeded` → ledger корректируется.
- [ ] **ОФД настроен и подключён** (Платформа ОФД или АТОЛ Онлайн) — иначе 54-ФЗ нарушается при работе с физлицами.
- [ ] Email чека работает (`from_email` валидный, SMTP настроен) — см. [Production checklist SMTP](/wiki/setup-smtp#production-readiness-checklist).
- [ ] **Disaster mode** протестирован: при недоступности ЮKassa виджет уступает место сообщению «оплатите в клинике» + manager cash activation работает.
- [ ] Алерт super_admin в Telegram настроен на массовые `payment.failed`.
