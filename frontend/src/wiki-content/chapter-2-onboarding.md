# Глава 2. Self-service onboarding

## Цель

Снять у будущего владельца франшизы сопротивление «надо звонить менеджеру». Цель — за 15 минут от первого визита на сайт до активного тенанта с заведённой клиникой и первым приглашённым сотрудником. Бизнес-задача: получить максимум франшиз без расширения штата продаж.

## Что реализовано

- **5-шаговый wizard** регистрации франшизы прямо из публичной страницы.
- **Trial 14 дней** автоматически активируется на момент завершения wizard.
- **OTP-верификация** телефона на шаге 1 (SMS через провайдер тенанта по умолчанию).
- **Welcome email** с инструкцией, паролем для первого входа и ссылкой на быстрый старт.
- **Самостоятельная активация модулей** в первые 30 дней — без подтверждения super_admin (с лимитом по сумме).

## Шаги wizard

| Шаг | Что собираем | Что валидируем |
|---|---|---|
| 1. Контакт | Имя, телефон, email | OTP на телефон |
| 2. Бизнес | Название сети, количество клиник | Уникальность slug |
| 3. Регион | Страна, регион, город | GeoIP сверяет с заявленным |
| 4. План | Basic / Professional / Enterprise | Trial по умолчанию |
| 5. Подтверждение | Согласие 152-ФЗ, оферта | Простая электронная подпись (OTP) |


### Welcome email

Email отправляется автоматически. Шаблон в `app/templates/emails/welcome_owner.html`. Содержит:

- Приветствие
- Пароль для входа
- Быстрый старт (5 пунктов)
- Контакты поддержки
- Ссылку на quick wins (создать первого сотрудника, подключить модуль)

## Где найти в UI

- Публичный wizard: `/onboarding` (доступен всем).
- Для super_admin: `/admin/onboarding/sessions` — мониторинг сессий, ручное вмешательство.
- В кабинете owner после завершения: `/admin/quick-start` — checklist первых действий.

## Backend модели

| Таблица | Описание |
|---|---|
| `onboarding_sessions` | хранит шаги wizard, токены OTP, истёчёт через 24ч |
| `tenants` | создаётся на финальном шаге |
| `users` | owner создаётся с временным паролем |
| `consents` | подписи 152-ФЗ и оферты |

## Зависимости

- **Гл. 1** — `/admin/tenants` создаёт тенант (тот же endpoint, разные wrappers).
- **Биллинг** — trial активируется через `subscriptions.create_trial`.
- **Уведомления** — email через `app/services/email.py`.

## Trial — что внутри

Триал — это статус `tenant.status = "trial"` + поле `trial_ends_at`. За 3 дня до конца триала шлётся email + Telegram-уведомление. По истечению — статус переходит в `unpaid`, а через 7 дней — в `suspended`.

Ограничения триала:

- Все функции базового плана доступны
- Модули можно подключить, но они не биллятся в trial
- Максимум 1 клиника и 10 пользователей
- Максимум 200 направлений

## Настройки администратора

- `ONBOARDING_TRIAL_DAYS` — длина триала (по умолчанию 14)
- `ONBOARDING_OTP_TTL_SECONDS` — TTL OTP (по умолчанию 600)
- `ONBOARDING_AUTO_APPROVE` — авто-одобрение без модерации super_admin (по умолчанию true)
- `WELCOME_EMAIL_TEMPLATE_ID` — id шаблона welcome email

## FAQ

**Что если slug уже занят?** Wizard на шаге 2 проверяет уникальность через AJAX и предлагает 3 свободных альтернативы.

**Можно ли пройти без OTP?** Нет. OTP — обязательный шаг для лиц, подписывающих согласие 152-ФЗ.

**Куда уходит trial-данные после suspend?** Хранятся 90 дней, потом анонимизируются. Можно восстановить через активацию подписки.

**Можно ли поменять план в трале?** Да, через `/admin/billing/plan`. Скидки/премии применяются после окончания триала.
