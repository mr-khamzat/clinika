# Глава 5. Скорость регистратора

## Цель

Регистратор — самая «горячая» роль в клинике, через него проходит каждый пациент. Цель — каждое типовое действие должно занимать не больше 5 секунд. Бизнес-смысл: не нанимать дополнительного регистратора с ростом потока; снизить ошибки, ускорить очередь у стойки.

## Что реализовано

- **Quick-actions с горячими клавишами** — основные операции одной клавишей.
- **Печать направления в PDF** одним кликом, с QR и 5-значным backup-кодом.
- **Mobile-First форма пациента** — оптимизирована под планшет на стойке.
- **Универсальный поиск Cmd+K** по пациентам, направлениям и приёмам.
- **Автоподстановка из МИС** — если пациент есть в Renovatio, его данные подтягиваются.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `N` | Новый пациент |
| `R` | Новое направление |
| `A` | Новая запись на приём |
| `S` | Сканировать QR |
| `Cmd+K` / `Ctrl+K` | Универсальный поиск |
| `Esc` | Закрыть модал / очистить поиск |
| `Enter` (в форме) | Сохранить и перейти к следующему |
| `Shift+P` | Печать последнего направления |

## API endpoints

### Быстрый поиск

```http
GET /reg/search?q=иван&limit=20
```

Поиск по `last_name`, `first_name`, `phone` (последние 4 цифры), `short_code` направлений, `appointment.id`.

### Создание пациента (минимальный набор)

```http
POST /reg/patients/quick
```

```json
{
  "phone": "+79001234567",
  "last_name": "Иванов",
  "first_name": "Иван"
}
```

Возвращает только что созданного пациента + флаг `auto_filled_from_mis: true/false`.

### Создание направления одним запросом

```http
POST /reg/referrals/quick
```

```json
{
  "patient_phone": "+79001234567",
  "to_clinic_id": "...",
  "service_id": "...",
  "template_id": "...",
  "print_pdf": true
}
```

Response:

```json
{
  "referral_id": "...",
  "short_code": "47281",
  "qr_url": "https://клиниксеть.рф/q/abc",
  "pdf_url": "/api/reg/referrals/{id}/pdf"
}
```

### Печать направления PDF

```http
GET /reg/referrals/{id}/pdf
```

Возвращает PDF (A4, шрифт PT Sans 12pt) с QR-кодом, 5-значным кодом, инструкциями, контактами клиники.

### Сканирование QR

```http
POST /reg/scan
```

```json
{ "qr": "https://клиниксеть.рф/q/abc..." }
```

Response — данные пациента и направления, кнопка «Подтвердить визит».

## Где найти в UI

Кабинет reg (`/admin` с ролью reg, упрощённая навигация):

- **Главная** — поиск Cmd+K, список приёмов на сегодня, быстрые действия.
- **Пациенты** — список с фильтрами.
- **Направления** — создание, подтверждение, печать.
- **Сканер** — большая кнопка на главной + страница `/reg/scan`.

## Backend модели

| Таблица | Описание |
|---|---|
| `patients` | пациенты клиники |
| `referrals` | направления |
| `appointments` | записи на приём |
| `reg_quick_actions` | счётчики действий (для аналитики UX) |

## Зависимости

- **Гл. 4: Manager** — manager создаёт правила, reg ими пользуется.
- **МИС-интеграция** — для автоподстановки данных пациента.
- **Гл. 8: Пациент** — направления и записи попадают в кабинет пациента.

## Mobile-First

UI рассчитан на 10" планшет в портретной ориентации. Минимальные касания, крупные кнопки, форма пациента — один экран без скролла. Тестировался на iPad 10.2", Samsung Tab A8, Xiaomi Pad 6.

## Настройки администратора

- `REG_AUTO_FILL_FROM_MIS` — авто-подстановка из МИС (default true).
- `REG_PRINT_TEMPLATE_ID` — id шаблона PDF.
- `REG_SHORT_CODE_TTL_DAYS` — срок жизни 5-значного кода (default 90).

## FAQ

**Что если МИС недоступна?** Форма пациента откроется пустой, regis вводит вручную. Синхронизация догоняет в фоне.

**Можно ли отменить отправку SMS пациенту?** Да, в форме создания направления — флажок «Не отправлять SMS».

**PDF не печатается на старом термопринтере.** Используйте альтернативный шаблон `compact_57mm` через параметр `?template=compact_57mm`.

**Можно ли создавать несколько направлений за один раз?** Да, через шаблоны пакета направлений (`bundle templates`) — manager настраивает, reg выбирает «Пакет: первичный приём + анализы + УЗИ».
