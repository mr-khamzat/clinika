# Глоссарий терминов

Эта статья — справочник основных терминов платформы. Используется как опорная при чтении остальной документации.

## A

**Acquisition Manager (менеджер по привлечению)** — внутренняя роль, которая ищет и подписывает врачей-партнёров и приходящих врачей. Получает бонус от объёма направлений своих подопечных.

**Activity Log** — журнал бизнес-действий пользователя (создал запись, отменил приём). Доступен в кабинетах manager и franchise_owner. Отличается от `audit_log` тем, что показывается клиенту и не содержит технических полей.

**Appointment (запись на приём)** — основная финансовая сущность. Связана с пациентом, врачом, клиникой, услугой и слотом расписания. Имеет статусы `created → confirmed → in_progress → completed/cancelled/no_show`.

**Audit Log** — системный журнал безопасности. Пишется автоматически декоратором `@audited`. Содержит IP, user-agent, дельту изменения. Не удаляется на уровне БД.

## B

**Billing Cycle (биллинг-цикл)** — период оплаты подписки. Поддерживаются: `monthly`, `quarterly`, `semi_annual`, `nine_months`, `annual`. Чем длиннее цикл, тем больше скидка.

**Billing Ledger** — двойная запись всех финансовых операций тенанта и пользователя. Каждая операция — пара `debit/credit` с обязательной балансировкой.

**Bonus** — денежное вознаграждение партнёру, врачу или рекрутеру. Имеет жизненный цикл `accrued → payable → paid`, удержание 14 дней.

## C

**Cabinet (кабинет)** — UI-раздел для конкретной роли (`/admin`, `/manager`, `/p/`). Содержит навигацию, доступную только этой роли.

**Cabinet Override** — техническая опция, позволяющая franchise_owner-у временно перевести пользователя в роль manager для разбора инцидентов. См. также **Impersonation**.

**Cash Activation** — оплата подписки пациента наличными через manager-а в клинике. Альтернатива онлайн-оплате через ЮKassa. Активируется для модуля «Здоровье+».

**Clinic (клиника)** — конкретная точка в сети. У одного тенанта может быть много клиник. Каждая клиника имеет адрес, расписание, штат врачей, услуги.

**Cohort (когорта)** — группа клиник или пациентов, привязанная к месяцу регистрации. Используется в когортной аналитике franchise_owner.

## D

**Direct Billing** — мгновенный расчёт между клиникой и visiting/partner врачом сразу после завершения приёма, без задержки на 14-дневное удержание. Применяется при стабильной истории сотрудничества.

**Disaster Mode** — режим работы платформы при отказе внешних сервисов (ЮKassa, ОФД, AI). Включает локальный fallback: ручной режим оплат, отложенная фискализация, заглушка AI.

## E

**E-signature (электронная подпись)** — простая электронная подпись через SMS-код для согласий 152-ФЗ, регламентов и актов. Не равна КЭП и не используется для финансовых документов.

**Enterprise** — тарифный план без жёстких лимитов с кастомным SLA.

## F

**Franchise (франшиза)** — синоним тенанта. Подразумевает наличие нескольких клиник под общим брендом.

**Franchise Owner (владелец франшизы)** — корневой пользователь тенанта. Создаёт клиники, назначает manager-ов, подписывается на тарифы и модули.

**FranchiseInvoice** — платёжный документ тенанта к платформе (за подписку и модули).

## G

**GeoIP** — определение страны/региона по IP. Используется для региональной блокировки франшиз (Region Lock).

## H

**Health+ (Здоровье+)** — премиальная подписка пациента. Активируется отдельным модулем у тенанта, даёт безлимит чата с врачом, скидки на услуги, monthly supply бонусов.

**Heatmap (загрузка врача)** — визуализация загрузки врача по дням недели и часам. Используется manager-ом для оптимизации расписания.

## I

**Impersonation** — функция, при которой super_admin или franchise_owner входит в систему от имени другого пользователя. Реализована по RFC 8693 token exchange. Любое действие в режиме impersonation помечается в audit log.

**InterClinicInvoice** — внутренний счёт между клиниками одной сети (когда направление выполнено и нужно зачислить бонус из бюджета принимающей клиники в бюджет направляющей).

## M

**MIS (МИС)** — медицинская информационная система клиники. Платформа интегрируется с МИС Renovatio через REST API.

**Module (модуль)** — подключаемая платная функция (телемедицина, лояльность, реклама). Активируется в marketplace, биллится отдельной подпиской.

**Multi-Tenancy** — архитектурный подход, при котором одна инсталляция платформы обслуживает множество тенантов с изоляцией данных.

## O

**Onboarding Wizard** — 5-шаговый мастер регистрации новой франшизы. Заканчивается активным тенантом с 14-дневным триалом.

**OTP** — одноразовый код по SMS или Telegram. Используется при онбординге, восстановлении пароля и подтверждении регламентов.

## P

**Partner Doctor (врач-партнёр)** — внешний врач, который направляет пациентов в клиники сети за бонус. Не имеет приёмов в сети.

**Patient (пациент)** — физическое лицо, получающее медицинскую услугу. Имеет личный кабинет, медкарту, семейный профиль.

**Plan (тарифный план)** — Basic / Professional / Enterprise. Определяет лимиты тенанта.

**Plan Override** — индивидуальный тариф, который franchise_owner устанавливает для конкретной клиники в сети (скидка или премия).

**PBKDF2** — алгоритм хеширования паролей с солью и большим числом итераций. Используется платформой вместо bcrypt по требованиям 152-ФЗ.

## R

**RBAC (Role-Based Access Control)** — модель доступа по ролям. Каждый эндпоинт имеет зависимость `require_role("...")`.

**Recruiter (рекрутер)** — пользователь, привлекающий врачей-партнёров. Получает % от направлений своих партнёров.

**Region Lock** — географический контроль франшизы. Включает мягкий режим (алерт при заходе из неразрешённого региона) и жёсткий (блокировка).

**Referral (направление)** — направление пациента из одной клиники в другую. Имеет QR-код, 5-значный backup-код и жизненный цикл.

## S

**SLA (Service Level Agreement)** — гарантированный уровень доступности (99.5% для Professional, 99.9% для Enterprise).

**SLI / SLO** — измеряемые показатели качества (latency, error rate) и пороги для них.

**Slot (слот)** — временной отрезок расписания врача, который можно занять записью.

**SOP (Standard Operating Procedure)** — регламент, описывающий, как должен действовать сотрудник в стандартной ситуации. Подписывается через простую электронную подпись.

**Super Admin (супер-админ)** — глобальный администратор платформы, видит все тенанты. Один-два человека на всю установку.

## T

**Tenant (тенант)** — изолированная единица платформы, обычно равная франшизе. Каждая запись данных принадлежит ровно одному тенанту.

**Tenant API Key** — ключ для доступа внешних систем тенанта к Public API v1. Прав может быть как у конкретной роли.

**Tenant Module Subscription** — связка тенант↔модуль с датами активации, ценой override и статусом.

**Token Exchange** — стандарт RFC 8693 для безопасного обмена одного JWT на другой (с пониженными правами или от имени другого пользователя).

**Trial (триал)** — 14-дневный бесплатный период для новых тенантов. Полный функционал базового тарифа без модулей.

## V

**Visiting Doctor (приходящий врач)** — врач, работающий в нескольких клиниках по контракту с фиксированной ставкой или % split. Биллинг — direct billing после приёма.

**Vitals (показатели здоровья)** — физиологические данные пациента (давление, пульс, вес, сахар), которые ведутся в личном кабинете и доступны врачу.

## W

**Webhook** — POST-уведомление платформы внешним системам тенанта о событиях (`referral_created`, `payment_received`). Подписывается HMAC-SHA256.

**White-Label** — модуль брендирования: свой логотип, цвета, кастомный домен. Скрывает упоминания «КлиникСеть» в публичном UI пациента.
