# Глава 7. Регламент-конструктор

## Цель

Дать сети возможность писать и распространять регламенты (Standard Operating Procedures, SOP) без юристов и Word-документов: визуальный конструктор, версионирование, AI-помощник, простая электронная подпись сотрудников. Бизнес-смысл: сократить «не знал», «не было в инструкции» инцидентов; ускорить онбординг новых сотрудников.

## Что реализовано

- **Wizard SOP** — шаги: тип, цель, шаги, проверка, аудитория.
- **Версионирование** — каждая правка создаёт новую версию, старые читабельны.
- **AI-генератор** — Gemini на основе пары пунктов делает черновик регламента.
- **E-signature** — простая электронная подпись через OTP по SMS.
- **Tracking прочтения** — кто из сотрудников открыл, прокрутил, подписал.

## Структура SOP

| Поле | Описание |
|---|---|
| title | Название |
| scope | Тенант / клиника / роль / врач (множественное) |
| version | semver-like (1.0.0) |
| status | draft / published / archived |
| sections | список разделов (markdown) |
| acknowledgements | подписи сотрудников |
| effective_from | дата вступления в силу |

## API endpoints

### CRUD регламентов

```http
GET    /regulations
POST   /regulations
GET    /regulations/{id}
PATCH  /regulations/{id}
POST   /regulations/{id}/publish
GET    /regulations/{id}/versions
GET    /regulations/{id}/versions/{ver}
```

### AI-генератор

```http
POST /regulations/ai/draft
```

```json
{
  "topic": "Обработка термопринтера на ресепшене",
  "context": "Используем Star TSP143. Бывает заминается бумага. Реагировать должен reg.",
  "audience": "reg"
}
```

Response:

```json
{
  "draft_md": "## Цель\n...\n\n## Шаги\n1. ...\n",
  "estimated_read_minutes": 3
}
```

### Подпись (acknowledge)

```http
POST /regulations/{id}/acknowledge
```

```json
{ "otp_code": "423817" }
```

Если OTP не отправлялся раньше:

```http
POST /regulations/{id}/request-otp
```

### Tracking

```http
GET /regulations/{id}/acknowledgements
```

```json
{
  "total": 23,
  "acknowledged": 18,
  "pending": 5,
  "by_user": [
    { "user_id": "...", "name": "...", "opened_at": "...", "signed_at": "..." }
  ]
}
```

## Где найти в UI

Кабинет manager / franchise_owner:

- **Регламенты** — список + CRUD.
- **Конструктор** — пошаговый wizard с превью.
- **AI помощник** — кнопка «Сгенерировать черновик».
- **Tracking** — таблица «кто подписал, кто нет».

Кабинет doctor / reg / nurse:

- **Мои регламенты** — список обязательных к ознакомлению.
- При входе после публикации — модальное окно «Новый регламент: %title%, ознакомиться».

| Таблица | Описание |
|---|---|
| `regulations` | сами регламенты |
| `regulation_versions` | история версий |
| `regulation_acknowledgements` | подписи |

## Зависимости

- **OTP сервис** (общий с onboarding и password reset).
- **Audit log** — каждая подпись пишется в audit.
- **Notifications** — сотрудники получают уведомление о новом регламенте.

## Юридическая сторона

Подпись через OTP по SMS — простая электронная подпись (ПЭП) согласно ст. 5 ФЗ-63 «Об электронной подписи». Подходит для внутренних документов клиники. Для документов с пациентами (информированное согласие 152-ФЗ) — отдельный механизм с обязательным сохранением IP и user-agent в момент подписания.

## Настройки администратора

- `REGULATIONS_REQUIRE_OTP` — обязательно ли OTP для подписи (default true).
- `REGULATIONS_AI_PROVIDER` — `gemini` / `disabled`.
- `REGULATIONS_REMIND_AFTER_HOURS` — через сколько часов напомнить, если не подписан (default 48).

## FAQ

**Можно ли отказаться подписывать?** Сотрудник может отметить «есть замечания», его подпись не зафиксируется, manager увидит замечание.

**Что если регламент устарел?** Создайте новую версию. После публикации старые подписи помечаются `outdated=true`, сотрудники получают новый запрос на подпись.

**Можно ли импортировать готовые SOP из Word?** Нет, импорт пока не реализован. Можно скопировать текст и вставить в конструктор.

**Хранятся ли старые версии?** Да, бесконечно. Подпись на старую версию остаётся валидной для своего периода.
