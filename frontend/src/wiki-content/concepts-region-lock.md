# Region Lock — географический контроль франшиз

Защита от того, что франшиза работает за пределами разрешённого региона. Бизнес-кейс: вы продали франшизу в Чечне, но обнаружили что подключают клиники в Дагестане без оплаты — Region Lock зафиксирует и пришлёт алерт.

## Как это работает

1. У франшизы (`Franchise`) задан `allowed_region` — например `Чеченская Республика`. Берётся из выпадающего списка в `Платформа → Франшизы → Region Lock`.
2. На каждый запрос к чувствительным эндпоинтам (создание клиник, направлений, врачей, бонусы, оплаты) — берётся IP пользователя, через `GeoLite2-City` определяется `geo_region`.
3. Если `geo_region` не совпадает с `allowed_region` — пишется `audit_log` с `action="region.violation"` и в Telegram владельцу платформы летит алерт.

## Три независимых режима

Включаются флагами per-franchise, никакой автоматики по умолчанию:

### 1. Алерты (Phase 1)
По умолчанию **включено** при заполненном `allowed_region`. Только запись + Telegram, никаких блокировок.

### 2. Auto-block по региону (Phase 2)
Тоггл `region_strict` — если `True`, при нарушении возвращает HTTP 403 на endpoint. **Не включайте** если у клиентов есть VPN или спутниковый интернет — будут ложные блокировки.

### 3. Manual block + IP whitelist (Phase 2 v2)
- `is_blocked` — ручная блокировка франшизы (со страницы «Нарушения регионов»). Можно с указанием срока (`blocked_until`).
- `franchise_ip_allowlist` — таблица разрешённых IP/CIDR. IP в whitelist обходит проверку региона. С флагом `bypass_block=true` — обходит и manual-блок (для временного разрешения конкретному IP).

## Где это видно в UI

- **Аудит → Нарушения регионов** — лента нарушений за период + сводка по франшизам. На каждой строке кнопки:
  - **«В whitelist»** — добавить IP в allowlist
  - **«Заблокировать»** / **«Разблокировать»** — manual-блок
- **Платформа → Франшизы → редактирование** — поле `allowed_region` + тоггл `region_strict` с предупреждением.

## VPN и спутник

В регионах массовых блокировок (Чечня, Ингушетия) пациенты часто ходят через VPN/Starlink — GeoIP даст левый регион. Поэтому рекомендованный сценарий:
- Активировать только Phase 1 (алерты)
- При получении алерта: связаться с пользователем, уточнить реальный IP
- Добавить IP в whitelist (или несколько, через CIDR `/24`)
